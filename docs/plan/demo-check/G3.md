## Findings for the kit and demo host (all products)

1. **Redirect URIs must use `localhost` for local HTTP.** `register-client` (`services/identity/src/cli.mjs:87`) refuses `http://127.0.0.1:<port>/` with "redirect must be https". Only `https:` or the host `localhost` are accepted. The brief's `http://127.0.0.1:<port>/` therefore cannot be registered. I used `http://localhost:<port>/` and `/signed-in`, and the products used `PUBLIC_URL=http://localhost:<port>`. This needs nothing for the real https demo host. For local runs, either update the brief or also allow `127.0.0.1` in `cli.mjs:87`.
2. **The identity service needs `IDENTITY_DEV_MODE=1` for a local HTTP issuer.** Without it the service refuses to start (`IDENTITY_PUBLIC_URL_MUST_BE_HTTPS`). The demo host uses https and must not set it.
3. **Mocks webhook secret.** Home Services refuses to start (`WEBHOOK_SECRET_REQUIRED`) without `ADS_MOCKS_WEBHOOK_SECRET` (or `HOME_WEBHOOK_SECRET`). The demo host should start the mocks with its own `MOCKS_WEBHOOK_SECRET` and give the same value to every product as `ADS_MOCKS_WEBHOOK_SECRET`.
4. **The `config/clients.demo.json` AfriCover `operator_setup` statement is wrong.** `INSERT INTO cover.platform_operators(tenant_id) VALUES (...)` fails with `null value in column "name"`, because `name` is `NOT NULL` with a length of 2–120. Change it to `INSERT INTO cover.platform_operators(tenant_id, name) VALUES ('<staff tenant id>', 'ADS Staff – AfriCover operator')`.
5. **`config/clients.demo.json` needs a PMP `operator_setup`.** It has none, but PMP needs one (see PMP below).
