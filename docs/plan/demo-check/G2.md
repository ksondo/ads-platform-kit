**Products:** Career Path, Nutrition, Personal Finance (PLFI), Morphoo (`go-ahead-guesser`), Logistics, MamaCare.

**Set-up**
- Kit: `build/demo-accounts-20261020` at `40fad53`.
- The identity service ran with `ADS_ENV=demo`, `DEMO_MODE=1`, `DEMO_SHOW_CREDENTIALS=1` and `IDENTITY_DEV_MODE=1` (for plain http) on `127.0.0.1:31095`, with the kit mocks on `31096`. - Each product ran from `origin/main` in its own worktree, on its own port from `audit/ports.txt`.
- One Playwright script (not committed) did these steps for every product:
  1. opened the product's own **Sign in** button;
  2. on the hosted page, checked the demo panel and clicked **Use demo account**, then **Continue**;
  3. picked the product's demo organisation, ran the role home and key screens, then signed in again into the staff organisation for staff screens;
  4. signed in as the demo admin and opened the admin screen;
  5. signed out, then confirmed the ADS session had ended (the login form shows again).

  A screen counts as PASS only when its main element is visible, no denied or error state is shown, and no product API call returned 4xx/5xx.

## Setting found for every product

- **Redirect URIs must use `localhost`, not `127.0.0.1`, for plain http.** `register-client` refuses `http://127.0.0.1:<port>/` ("redirect must be https") and allows only `localhost` (`services/identity/src/cli.mjs:87`). The brief asked for `http://127.0.0.1:<port>/`, so I registered `http://localhost:<port>/` instead. The hosted demo uses https, so this affects local checks only.
