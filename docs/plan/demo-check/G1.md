## Settings found for every product

- **Redirect URIs must use `localhost`, not `127.0.0.1`, for plain http.** `register-client` refuses `http://127.0.0.1:<port>/` ("redirect must be https") and allows only `localhost` (`services/identity/src/cli.mjs:87`). I registered `http://localhost:<port>/` instead (G2 found the same). The hosted demo uses https, so this affects local checks only.
- **No product has a demo seed.** Every product starts empty: no shop products, no venture, no fleet assets, no savings group. The demo is usable, but much less convincing. One small seed per product (listed below) would let a visitor see real records.

## Per product

### Commerce (`ads-commerce-platform`): NEEDS CONFIG

- **Demo admin: FAIL as configured.** In `config/clients.demo.json` Commerce has `admin_roles: []`. So `demo-orgs` gives the demo admin no Commerce role. Sign-in skips the workspace picker, lands in the personal workspace with only `commerce_buyer`, and `/commerce/merchant/staff` says "You don't have access to this shop's workspace".
  - **Config fix (tested):** set `"admin_roles": ["merchant_owner"]` for Commerce in `config/clients.demo.json`. With that change and a re-run of `demo-orgs`, the demo admin picks "ADS Demo – Commerce shop", gets `merchant_owner`, and **Staff and receipts** lists both demo accounts. Result: PASS.
- **Operator note in the client list is wrong.** `operator_setup` says `capability --capability BANK_COLLECTION --tenant <bank tenant id>`. Bank collection is switched on per **shop**, so it needs the *main* (shop) tenant id, and the command also needs `--enabled true`. What I ran (both worked):
  - `register-bank --tenant <bank> --name "ADS Demo Bank (mock)"`
  - `capability --tenant <main> --capability BANK_COLLECTION --enabled true`
- **Screens checked:** merchant overview (role home), marketplace, catalogue, merchant orders, cash POS, cash on hand, buyer orders, account. All PASS with the `main` workspace roles `commerce_buyer, merchant_owner, commerce_manager, commerce_cashier, commerce_accountant`.
- **Env the demo host must set:**
  - **API:** `OIDC_ISSUER`, `OIDC_AUDIENCE=commerce-web`, `OIDC_JWKS_URL`, `API_PORT`;
  - **database:** `DATABASE_URL` (runtime login in `commerce_runtime`; migrate as owner with `npm run migrate`);
  - **secrets and callbacks:** `COMMERCE_HANDOVER_SECRET` (32+ characters), `COMMERCE_PUBLIC_API_URL` (bank callback);
  - **mocks:** `ADS_MOCKS_URL` and `ADS_MOCKS_WEBHOOK_SECRET` for the mock bank and SMS.
  - **Web build:** `ADS_IDENTITY_URL`, `ADS_IDENTITY_CLIENT_ID=commerce-web`, `COMMERCE_PUBLIC_URL`, and `COMMERCE_API_URL` for the `/api` proxy.
- **Watch out:** with `NODE_ENV=production`, Commerce turns the mocks off and blocks buyer orders, reservations and POS writes (unless `ADS_COMMERCE_OPERATIONS_APPROVED=true`). The demo host must therefore **not** run Commerce with `NODE_ENV=production`, or the journeys go read-only.
- **Seed wanted:** one published product in the demo shop (owner draft, then review by the ADS staff org's `commerce_reviewer`). Without it the marketplace and catalogue are empty.

### VentureWorks (`africa-digital-synergy-ventureworks`): NEEDS FIX

- **Defect: blank page after sign-in when the organisation has no venture yet.** That is always the case on a fresh demo. Sign-in returns to `/`, and React crashes with `TypeError: Cannot read properties of null (reading 'id')`, leaving a white page with no menu and no sign-out.
  - **Cause:** `src/app/screens/ReadinessDashboard.tsx:10` calls `useLoad(s => api(`/v1/ventures/${venture!.id}/…`))` *before* its `if (!venture)` check. `useLoad` (`src/app/ui.tsx:32-36`) calls `load()` synchronously inside `useEffect`, so the null dereference throws outside the promise chain and unmounts the app.
  - **Same pattern** in `MaturityScreen`, `DocumentsScreen`, `LegalScreens`, `PaymentsScreen`, `WorkScreens`, `InvestmentScreen`, `PlanScreens` and `AssessmentScreen`. Opening `#assessment` with no venture crashes in the same way.
  - **Suggested fix (one place):** in `useLoad`, run the loader as `Promise.resolve().then(() => load(c.signal))` so a synchronous throw becomes a rejected promise. The screens already render `NeedVenture` ("start a venture") when `venture` is null. Alternatively, skip the load when there is no venture. Add a Playwright test: a founder with zero ventures signs in and sees the empty state.
- **After a venture exists**, everything passes:
  - The script created "Demo Maize Seeds" through Founder intake.
  - The venture home and Assessment, Business blueprint, Roadmap and KPIs, Plan approval, My tasks, and Evidence and review: 6/6 PASS.
  - The demo admin (`tenant_admin`) opened Administration › Access and › Audit: PASS.
  - Sign out (account menu): PASS.
  - A fresh database gave the same result.
- **Env the demo host must set:**
  - **sign-in:** `OIDC_ISSUER`, `OIDC_AUDIENCE=ventureworks-web`, `OIDC_JWKS_URL`, `ADS_IDENTITY_URL`, `ADS_IDENTITY_CLIENT_ID`, `VW_PUBLIC_URL`;
  - **database:** `DATABASE_URL` (runtime login, member of `ventureworks_api`) and `MIGRATION_DATABASE_URL`;
  - **test mode:** `VW_TEST_MODE=true`, `VW_PAYMENTS_MODE=mock`, `VW_RAG_MODE=mock`, `VW_EMAIL_MODE=mock`, `ADS_MOCKS_URL`, `ADS_MOCKS_WEBHOOK_SECRET`;
